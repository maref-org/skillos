# 13. SkillOS 错误预算

## 1. SLO 与错误预算定义

### 1.1 核心 SLO

| SLO | 目标 | 测量周期 | 错误预算 |
|-----|------|---------|---------|
| 可用性 | 99.9% | 30 天 | 0.1% = 43.2 分钟 |
| 响应时间 P99 | < 500ms | 7 天 | 1% 请求可超时 |
| 错误率 | < 0.1% | 7 天 | 0.1% 请求可失败 |
| 数据持久化 | 100% | 30 天 | 0（零容忍） |

### 1.2 错误预算计算公式

```
错误预算 = (1 - SLO) × 总请求数

示例：
- 30 天总请求数 = 1,000,000
- 可用性 SLO = 99.9%
- 错误预算 = 0.1% × 1,000,000 = 1,000 次失败请求
```

## 2. 错误预算消耗监控

### 2.1 消耗速度分级

| 消耗速度 | 定义 | 行动 |
|---------|------|------|
| 健康 | < 50% / 周期 | 正常迭代 |
| 警告 | 50% - 75% / 周期 | 暂停新功能，优先稳定性 |
| 危险 | 75% - 100% / 周期 | 冻结发布，全员 on-call |
| 耗尽 | > 100% / 周期 | 启动事故响应，强制回滚 |

| 可用性 | 2026-05 | 0% | 健康 |
| 响应时间 | 2026-05 | 0% | 健康 |
| 错误率 | 2026-05 | 0% | 健康 |

## 3. 错误预算与发布策略

- **预算充足（< 50%）**：正常发布，可包含新功能
- **预算警告（50% - 75%）**：仅发布 Bug 修复，禁止新功能
- **预算危险（> 75%）**：禁止任何发布，专注稳定性修复

## 4. 例外处理

以下情况不计入错误预算：

1. 计划内维护窗口（提前 24h 通知）
2. 第三方服务故障（超出控制范围）
3. 不可抗力（网络运营商故障等）

## 5. 复盘机制

每次错误预算耗尽触发：

1. **事故复盘**：24 小时内完成
2. **根因分析**：5 Whys 方法
3. **改进措施**：必须包含可验证的预防措施
4. **预算重置**：下周期开始时重置
